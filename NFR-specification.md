# AI Document Audit System - Non-Functional Requirements

| NFR ID | Category | Requirement | Target / Acceptance Criteria | Solution |
| --- | --- | --- | --- | --- |
| NFR-1 | Performance | Interactive NL queries should return a first meaningful response quickly, and audit runs should complete within an agreed SLA. | - First token or summary in under 2 seconds at p95. <br>- 95% of audit runs complete within 10 minutes per package. <br>- End-to-end completion under 15 minutes at p99. | A. Streaming + caching: Stream tokens from Azure OpenAI over Server-Sent Events so the first token lands under the 2 second p95 target, and cache embeddings plus frequent query results in Redis to keep repeat queries fast. <br><br> B. Two-tier retrieval + precomputation: Use cheap vector top-k retrieval plus reranking to keep query latency low, and precompute document summaries during ETL so audit runs finish within the 10 minute and 15 minute targets instead of generating everything on demand. |
| NFR-2 | Scalability | The system must absorb bursty submission and query load without degrading interactive latency. | - Sustain at least 500 document submissions per hour. <br>- Support 50 concurrent interactive queries. <br>- Keep p95 query latency under 3 seconds during burst periods. | A. Queue-depth autoscaling: Scale Celery workers horizontally from Redis queue depth so the pipeline can sustain 500 submissions per hour, and scale AI Search replicas/partitions to hold p95 query latency under 3 seconds at 50 concurrent users. <br><br> B. Staged pipelines: Split ETL into separate extract, chunk, embed, and index queues so each stage can scale independently under burst load without pushing query latency above the 3 second p95 target. |
| NFR-3 | Availability | Target high availability for the interactive path and ensure no submitted document or audit result is silently lost. | - Achieve 99.9% monthly availability. <br>- Keep recovery time objective (RTO) under 30 minutes. <br>- Keep recovery point objective (RPO) under 15 minutes. <br>- Maintain zero silent data loss. | A. Managed, redundant services: Use zone-redundant Azure services and health probes so the interactive path can meet 99.9% monthly availability, while storage redundancy and multi-replica search reduce downtime and data-loss risk. <br><br> B. Idempotent, retryable tasks: Make Celery tasks idempotent with automatic retries and a dead-letter queue so failed extraction or audit work can be recovered within the 30 minute RTO, preserve the 15 minute RPO, and avoid silent loss of submitted documents or results. |
| NFR-4 | Security | All data in transit is encrypted, only user sensitive information is encrypted at rest, secrets are never stored in code, and internal service-to-service traffic is not publicly reachable. |  | A. Identity + secrets hygiene: Authenticate via Entra ID (OAuth2/OIDC) with short-lived JWTs validated in FastAPI dependencies; use managed identities and Azure Key Vault for all secrets/keys; encrypt only sensitive fields at rest in the application or database layer; enforce TLS everywhere. <br><br> B. Private networking: Place backend, stores, and Azure services behind a VNet with private endpoints so Blob, AI Search, and OpenAI have no public exposure. |
